# Local LLM Support Overhaul — Design

**Date:** 2026-06-20
**Branch:** `feat/local-llm-overhaul`
**Status:** Approved via interactive prototype (`~/reports/t3code/2026-06/2026-06-20-local-llm-prototype.html`)

## Goal

Replace the runtime auto-detection of local LLM providers/models with a **fixed,
build-time catalog** (curated from the local-LLM providers runbook) plus a
**user-curated list of model configurations**. Make the relationship explicit:
providers (servers) → model configs (a model pinned to a provider) → sidebar
load/unload → coding-agent env-var presets.

## Decisions (locked)

1. **Build-time catalog is hand-curated and committed** — not parsed from the
   prose runbook at build time, not generated by a codegen step. A static data
   module is the source of truth.
2. **Catalog-only models** — drop all filesystem scanning / `ps` discovery. The
   model dropdown is sourced solely from the catalog.
3. **Managed = mlx-serve + ds4 only** — these two can be spawned/killed by
   t3code. vLLM / llama.cpp / LM Studio / Ollama are configurable + probe-only
   (env-var preset targets), never spawned.
4. **Clean redesign + migrate** — introduce the new schema, migrate existing
   `localModels` settings into it, and remove the old auto-detect code paths.
5. **One merged Settings tab** — "Local LLM" holds both a *Providers* section
   and a *Model configurations* section. The cloud-agent "Providers" tab stays
   separate.
6. **Provider toggle is visibility-only** (eye icon), not enable/disable — a
   hidden provider is still fully configurable and usable; visibility only
   controls whether it appears in model-config pickers.
7. **Args are chosen from a per-provider CLI-flag catalog** (a popover menu with
   flag descriptions and enum/number/string value inputs), curated from each
   provider's `--help`.

## Architecture

Three layers change: shared catalog data, contracts (settings + RPC schema),
server (process manager), web (settings UI + sidebar + presets).

### 1. Static catalog — `packages/shared/src/localLlm/`

`packages/contracts` is schema-only, so the catalog **data** lives in
`packages/shared` (runtime utilities, subpath-exported as
`@t3tools/shared/localLlm`). Consumed by both server and web.

```ts
type LocalLlmFormat = "mlx" | "gguf" | "safetensors";

interface ProviderCatalogEntry {
  id: string;              // slug, e.g. "mlx-serve"
  name: string;            // display
  managed: boolean;        // t3code can spawn it (mlx-serve, ds4)
  format: LocalLlmFormat;  // which model format it serves
  host: string;            // default bind/probe host
  defaultPort: number;     // runbook default port
  binaryPath?: string;     // managed: default executable (PATH name or path)
  modelsDir?: string;      // managed: default dir holding model resources
  cwdFromBinary?: boolean; // managed: spawn cwd = dirname(binary) (ds4 metal shaders)
  defaultArgs: string[];   // runbook-recommended launch args (grouped tokens)
  note: string;            // shown in UI
}

interface ModelCatalogEntry {
  id: string;              // slug, e.g. "Qwen3.6-35B-A3B-4bit"
  name: string;            // display
  format: LocalLlmFormat;  // gates provider compatibility
  resourceName: string;    // dir (mlx) or file (gguf) name under provider.modelsDir
  quant?: string;
  moe?: boolean;
  maxContext: number;      // slider ceiling
  approxBytes: number;     // RAM-budget estimate
  ds4Only?: boolean;       // GGUF that only ds4-server should serve
  note?: string;
}

interface ArgSpec {
  flag: string;
  type: "flag" | "enum" | "number" | "string";
  values?: string[];       // enum
  placeholder?: string;    // number/string hint (documented default)
  desc?: string;
}

export const LOCAL_LLM_PROVIDERS: ProviderCatalogEntry[];
export const LOCAL_LLM_MODELS: ModelCatalogEntry[];
export const PROVIDER_ARG_SPECS: Record<string /*providerId*/, ArgSpec[]>;
export const compatibleModels(providerId): ModelCatalogEntry[]; // format match (+ ds4Only rule)
```

Catalog contents are taken verbatim from the runbook and the live
`mlx-serve --help` / `ds4-server --help` (see prototype for the exact data).
Compatibility rule: `model.format === provider.format`, and a `ds4Only` model
matches only the `ds4` provider (other GGUF servers accept non-`ds4Only` GGUF).

### 2. Settings schema — `packages/contracts/src/settings.ts`

Replace `LocalModelsSettings` with `LocalLlmSettings`:

```ts
LocalLlmProviderConfig = {   // sparse per-catalog-provider overrides
  visible?: boolean;         // default true
  host?: string;
  port?: number;             // default-port override
  binaryPath?: string;       // managed
  modelsDir?: string;        // managed
  baseUrl?: string;          // external probe URL override
  defaultArgs?: string[];    // overrides catalog defaultArgs when present
}

LocalLlmModelConfig = {
  id: string;                // stable slug/uuid
  name: string;              // defaults to model display name
  providerId: string;        // catalog provider id
  modelId: string;           // catalog model id
  contextWindow?: number;    // slider; default = model.maxContext
  visible?: boolean;         // default true (sidebar)
  port?: number;             // managed: stable port for this config (default assigned at create)
  argsOverride?: string[];   // overrides provider defaultArgs for this config
  modelPathOverride?: string;
}

LocalLlmSettings = {
  ramBudgetBytes: number;    // default 0 → 80% system memory
  providers: Record<providerId, LocalLlmProviderConfig>;  // default {}
  models: LocalLlmModelConfig[];                          // default []
}
```

- `ServerSettings.localLlm` (whole-object patch in `ServerSettingsPatch`, like
  the old `localModels`). Keep old `localModels` as an **optional, deprecated**
  field read only by migration.
- **Stable port (managed):** each managed model config owns a port so status can
  be re-probed deterministically across server restarts (replaces the dynamic
  8765–8799 pool + `ps` discovery). Default assigned at config creation = first
  free port in the provider's range; editable in Advanced. Duplicate-port
  configs are flagged in the UI.

#### Migration (decode transform)

When `localLlm` is absent but `localModels` is present:
- `localModels.ramBudgetBytes` → `localLlm.ramBudgetBytes`
- `localModels.modelsDir` / `defaultArgs` → `providers["mlx-serve"]`
- `localModels.ds4.{binaryPath,modelsDir,defaultArgs}` → `providers["ds4"]`,
  `providers["ds4"].visible = localModels.ds4.enabled`
- `localModels.perModel[k]` whose key matches a catalog model `resourceName` →
  seed a `LocalLlmModelConfig` with that model + matching provider, carrying
  `argsOverride`. Non-matching keys are dropped (logged).

### 3. Server — `apps/server/src/llm/LlmServeManager.ts`

- **Engines derived from catalog** managed providers (mlx-serve, ds4) rather than
  hardcoded; spawn arg builders stay per-engine (verbatim from prototype/runbook;
  mlx `--model <dir>`, ds4 `-m <file>` + `cwd = dirname(binary)`).
- **Remove** `ps`-scan discovery and filesystem enumeration. The loadable set is
  the user's `localLlm.models`. Loading a config resolves:
  `provider config (catalog + overrides) → host/port/binary/modelsDir/args`, and
  `model path = modelPathOverride ?? join(modelsDir, model.resourceName)`. A
  `stat()` existence check at load (not enumeration) yields a friendly error.
- **Status** = in-memory registry of this server's launches + a `/v1/models`
  probe of each config's resolved port (managed: config.port; external: provider
  baseUrl/port). Online iff reachable and the served model matches.
- **RAM budget** logic unchanged (sum online RSS + inflight estimates vs budget,
  estimate from `model.approxBytes`).
- Keep loopback-only, detached process groups, scope-based reaping, load
  serialization semaphore, symlink/path-traversal guard on resolved path.

### 4. RPC — `packages/contracts/src/rpc.ts`

- `WsLlmServeLoadRpc` payload `{ configId }`; `WsLlmServeUnloadRpc` payload
  `{ configId }` (manager maps to pid). Errors reuse `LlmServeError` (+ a new
  `external_not_managed` kind for attempts to load an external-provider config).
- `LlmModelsSample` adapted: per managed/used provider, `models[]` are
  config-derived (`configId`, `name`, status, meta, pid, port).

### 5. Web

- **New tab** `settings.local-llm.tsx` → `LocalLlmSettingsPanel` with two
  sections: `LocalLlmProvidersSection` (catalog cards, eye visibility, override
  fields, `ArgPickerMenu`) and `LocalLlmModelConfigsSection` (config cards:
  name, provider→compatible-model selects, context slider, Advanced accordion
  with `ArgPickerMenu` + port/path overrides, eye visibility).
- **Remove** the old `settings.local-models.tsx` + raw `LocalModelsSettings`
  editor; update `SettingsSidebarNav` (one "Local LLM" item, `CpuIcon`).
- **Shared** `ArgPickerMenu` component driven by `PROVIDER_ARG_SPECS`.
- **Sidebar** `SidebarLocalModels` sources rows from `localLlm.models` (visible)
  joined with the live status sample; click load/unload (managed only; external
  rows show an info tooltip and are not clickable to load).
- **Providers tab** gains a `Presets` button beside `+ Add`. Dialog: pick a model
  config → generate driver-aware env vars (base URL from provider host/port +
  `/v1`, an API key placeholder, the model name) → **merge into the instance,
  preset wins on conflict** (added/override rows highlighted). A small
  `driverKind → envVarNames` map produces the right variable names per driver.
- Hooks: `useLlmModels` unchanged shape; actions load/unload by `configId`.

## Testing (this phase — constraints)

**Unit tests only. No build run. No model-loading-to-GPU/integration tests** (the
machine is running experiments using GPU/memory). All of the following are pure
and runnable without spawning a server or loading a model:

- shared: `compatibleModels` rule; catalog integrity (unique ids, every model's
  format has ≥1 provider, arg-spec flag uniqueness).
- contracts: `LocalLlmSettings` decode defaults; **migration** from a
  representative legacy `localModels` blob; `ServerSettingsPatch` round-trip.
- server: config→spawn-arg resolution (mlx + ds4 arg vectors, cwd rule, path
  resolution + traversal guard) with the spawner **mocked**; RAM-budget math;
  port-assignment helper; status derivation from a faked probe + registry.
- web: `ArgPickerMenu` add/remove/enum/number flows; presets merge logic
  (preset-wins, driver var-name mapping); compatibility filtering in the model
  picker; migration-driven rendering. Logic extracted into `*.logic.ts` for
  node-unit testing where DOM isn't needed (existing pattern).

Deferred until the user signals: launching mlx-serve/ds4 for real, load/unload
round-trip, full `verify`/build, browser (Playwright) tests that exercise live
streams.

## Out of scope

- Launch recipes for vLLM/llama.cpp/LM Studio/Ollama.
- Re-surfacing externally-started processes the user launched by hand (the
  sidebar is now the curated config list by design).
- Ollama's `/api/ps` resident probe (still a future follow-up).
