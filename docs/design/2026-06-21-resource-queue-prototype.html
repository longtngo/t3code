Resource Queue — sidebar prototype

Live mock using a real resctl status --json snapshot (1 GPU job running, 3 queued). Hover or click the Resource Queue item in the footer to open the popup (click pins it open). Hover any row to reveal its full details. Durations tick live; the popup shows a simulated 5s refresh.

The popup list caps the visible area at ~5 rows, then scrolls (try “Busy”).

Quick-glance item (collapsed)

  • Counts — two badges: running (green, holding a lease) and waiting (yellow, queued across all resources). Each goes muted-grey when its count is 0.
  • Opens the popup on hover and on click (click pins it so it stays while you move the mouse away).
  • Updates every 60s in the background; every 5s while the popup is open.

Popup — fields I recommend

From the JSON each item exposes: resource, priority, reason, project, agent, pid, amount, seq, eta_sec, and a timestamp. I show the 5 that carry signal and drop the rest:

  • Resource badge (gpu / cpu / ram) — what it needs.
  • Priority badge — drives ordering & is colour-coded.
  • Reason — the human “what & ETA” string; the most useful single field (primary line).
  • Project — who owns it (secondary line).
  • Elapsed — running Xm (held) or waiting Xm (since enqueue); surfaces staleness.

Each row puts the reason on line 1 and the labels on line 2 (resource + priority badges, then project · elapsed). Running holders (green) are listed first so you see what’s blocking the queue, then waiting jobs (amber) by queue order. amount appears only when >1. A utilization strip up top shows in_use / capacity per resource.

Row detail → hover to peek, click to dismiss

Hovering a row expands a third line with the fields that don’t earn permanent space: pid, queue position (e.g. #2 in gpu queue), exact enqueued / started time, and eta. Click the expanded row to collapse it back to simple (handy when it covers the row below); moving the pointer away resets it. Nothing is truly hidden — just progressively disclosed.
